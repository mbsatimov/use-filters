---
title: resolveFilterParams
description: Compute the hook's params object outside React, for route loaders.
---

```ts
resolveFilterParams(configs, rawSearch, options?) => params
resolveFilterParams<P>(configs, rawSearch, options?) => params // checked against an API type
```

Builds the same `params` object that `useFilters` builds on mount, without React.
Use it in route loaders and server code so a prefetch lands under the same cache
key. The [Project setup](/docs/guides/project-setup#3-route-loaders-with-resolvefilterparams)
guide shows it in context.

## Arguments

- `configs`: the same config map you pass to the hook.
- `rawSearch`: the request's query, in whichever form your router gives you:
  - a parsed object, e.g. `{ status: 'open' }` (TanStack Router's `search`)
  - a `URLSearchParams`, e.g. `new URL(request.url).searchParams`
  - a query string, with or without the leading `?`, e.g. `location.search`
  - a full URL or path, e.g. `request.url` (2.0.1 and later)
- `options`: `{ arraySeparator, pagination }`. These must match what the hook uses,
  or the two produce different keys. [`defineFilters`](/docs/api/define-filters)
  sets them in one place.

## What it does

- Applies each filter's `defaultValue`, or `null`, the same way the hook does.
- Parses values to the same types: `?customer_id=5` gives the number `5`, not `'5'`.
- Adds the pagination params under your configured key names.
- Drops anything the hook wouldn't put in `params`, such as the `_label` params
  that async filters store.

```ts
const params = resolveFilterParams(productConfigs, new URL(request.url).searchParams);
// { search, status, page, per_page }, the same shape as the hook's params
```

## Checking against an API type

Passing `<P>` checks `configs` against your endpoint's params type and types the
result as `P`. The rules are the same as for
[`useFilters<P>`](/docs/guides/typed-params): required keys need a filter, and
non-null params need a `defaultValue`.

```ts
const params = resolveFilterParams<ProductListParams>(
  productConfigs,
  new URL(request.url).searchParams
);
// params: ProductListParams
```

<Callout>
  This is why `select` and `multiSelect` require a
  [`valueType`](/docs/filter-types/select-and-tags). The loader never sees the `options`, so it
  can't infer the value type from them. Declaring it means the hook and the loader parse the value
  the same way.
</Callout>

Pagination is built in. Unless you turn it off, `params` always has the page and
page size, read from the URL:

```ts
const { params } = useFilters(configs);
// params = { ...filters, page: 1, per_page: 10 }
```

Go to page 3 below, then change the status. The page drops back to 1, because
page 3 of the old results means nothing for the new ones:

## Key names

The keys default to `page` and `per_page`. Whatever you name them, the URL and
`params` use the same names, so there is no mapping to keep in sync. Set them
once with [`createFilters`](/docs/guides/project-setup):

```ts
export const { useFilters } = createFilters({
  pagination: { perPageKey: 'page_size', defaultPerPage: 25 }
});
// URL: ?page=2&page_size=25   params: { page, page_size }
```

## Changing the page

`useFilters` reads the page into `params`, but it doesn't render a pager or give
you a setter for it. Write the page with nuqs's `useQueryState`, using the same key
name and default:

```tsx
import { parseAsInteger, useQueryState } from 'nuqs';

const { params } = useFilters(configs);
const [, setPage] = useQueryState('page', parseAsInteger.withDefault(1));

<button disabled={params.page <= 1} onClick={() => setPage(params.page - 1)}>
  Previous
</button>;
```

`setFilter` won't work here. Pagination keys belong to the hook, so passing one to
`setFilter` is a type error.

When the page size changes, set the page back to the first page as well, since
the old offset no longer lines up.

## Going back to page 1

By default, changing any filter resets the page to the first one. Turn that off
if something outside the hook should own the page completely:

```ts
createFilters({ pagination: { resetPageOnFilterChange: false } });
// or for one call:
useFilters(configs, { pagination: { resetPageOnFilterChange: false } });
```

## Zero-based pages and offset/limit APIs

`firstPage` is where numbering starts. It's the value used when the URL has none
and the value a reset writes. It defaults to `1`; set it to `0` for an API that
counts from zero:

```ts
createFilters({ pagination: { firstPage: 0 } });
// first page: ?page=0, in the URL and in params
```

The same option covers offset/limit APIs. Name the keys after your API's params
and start the offset at 0:

```ts
createFilters({ pagination: { pageKey: 'offset', perPageKey: 'limit', firstPage: 0 } });
// params: { offset, limit, ...filters }
```

Then move forward by adding `limit` to `offset`:

```tsx
const [offset, setOffset] = useQueryState('offset', parseAsInteger.withDefault(0));

<button onClick={() => setOffset(offset + params.limit)}>Next</button>;
```

The two keys don't have to mean "page number". They are the two
pagination values the hook puts in `params` and resets on a filter change. Only
convert page numbers to an offset at fetch time if your UI actually shows page
numbers.

## Turning it off

Pass `pagination: false` for a screen without pages, such as a settings filter or
an infinite-scroll list. `params` then only has your filters, and nothing resets
when they change.

Every option is listed in the [`createFilters` reference](/docs/api/create-filters#pagination).
